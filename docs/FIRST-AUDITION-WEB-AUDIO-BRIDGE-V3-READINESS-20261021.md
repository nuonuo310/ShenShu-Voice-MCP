## Generated playback contract

For `source:"minimax"`, the browser path accepts only:

- `generated === true`;
- `audioMimeType === "audio/wav"`;
- no `audioUrl` field;
- canonical, bounded base64 of at most 3,000,000 characters;
- a complete RIFF/WAVE file of at most 2 MiB;
- PCM format, mono, 16 kHz, 16-bit, 32,000-byte-per-second data;
- one bounded data chunk with decoded duration from 0.2 through 60 seconds.

The generated branch validates the record before accepting it and does not call `inlineAudioUrl`, set `audio.src`, call `audio.load()` or call HTMLAudioElement `play()`. On click, it creates `AudioContext`/`webkitAudioContext` and starts `resume()` synchronously inside the user gesture, waits for the decode, creates one buffer source and starts it. No provider fetch or remote URL is introduced.

The generated path fails closed without fallback when:

- the record is malformed, oversized, URL-bearing, cross-source or wrong-generation;
- Web Audio is unavailable or resume/decode fails;
- decoded duration is outside the accepted bound;
- a newer host result arrives while decode is pending;
- a duplicate click arrives while decode is starting.

A second click while playing stops and disposes the active source/context. A newer result also stops and disposes the old source/context and invalidates the pending generation/token so a late decode cannot start.

The v2 pure-JavaScript helper `prepareGeneratedAudioPlayback()` remains for backward-compatible offline contract tests and still constructs its legacy data URL internally. It is **not** used by the browser generated branch: `ui/mcp-bubble.html` intercepts every `source:"minimax"` record before the legacy inline/fixture path. This is an explicit compatibility boundary, not a silent playback fallback.
